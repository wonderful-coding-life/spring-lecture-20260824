# PRD.md

## 1. 목표

회원이 가입하고 로그인하여 게시글을 작성할 수 있는 기본적인 웹 게시판을 구현한다.

---

## 2. 구현 범위

다음 기능을 구현한다.

- 회원가입
- 로그인과 로그아웃
- 게시글 목록 조회
- 게시글 상세 조회
- 게시글 등록
- 게시글 수정
- 게시글 삭제
- 게시글 페이징
- 작성자 권한 검사
- 입력값 Validation

---

## 3. 사용자와 권한

### 비로그인 사용자

다음 기능을 사용할 수 있다.

- 회원가입
- 로그인
- 게시글 목록 조회
- 게시글 상세 조회

### 로그인 사용자

비로그인 사용자의 기능과 함께 다음 기능을 사용할 수 있다.

- 로그아웃
- 게시글 등록
- 자신이 작성한 게시글 수정
- 자신이 작성한 게시글 삭제

다른 사용자가 작성한 게시글은 수정하거나 삭제할 수 없다.

## 4. 데이터 모델

### 4.1 Member

회원을 표현하는 Entity이다.

| 필드 | 설명 | 조건 |
|---|---|---|
| id | 회원 번호 | 기본키, 자동 증가 |
| username | 로그인 아이디 | 필수, 중복 불가 |
| password | 비밀번호 | 필수, BCrypt 암호화 |
| name | 이름 | 필수 |
| email | 이메일 | 필수, 중복 불가 |

### 4.2 Article

게시글을 표현하는 Entity이다.

| 필드 | 설명 | 조건 |
|---|---|---|
| id | 게시글 번호 | 기본키, 자동 증가 |
| title | 제목 | 필수, 100자 이하 |
| content | 내용 | 필수 |
| createdAt | 작성일 | 게시글 등록 시 설정 |
| author | 작성자 | Member와 다대일 관계 |

`Article`은 `Member`를 다대일 단방향 관계로 참조한다.

## 5. 데이터베이스 요구사항

- MySQL 문법으로 `support/schema.sql`을 작성한다.
- 스키마는 운영자가 수동으로 생성하며 애플리케이션이 자동 실행하지 않는다.
- `schema.sql`은 Entity 매핑과 일치해야 한다.

### 애플리케이션 설정

- 기본 애플리케이션은 MySQL을 사용한다.
- 데이터베이스 접속 정보는 환경 변수로 설정한다.
- `src/main/resources/application.properties`에 다음 환경 변수를 사용한다.

| 환경 변수 | 설명 |
|---|---|
| `DB_URL` | 데이터베이스 JDBC URL |
| `DB_USER` | 데이터베이스 사용자 이름 |
| `DB_PASS` | 데이터베이스 비밀번호 |

### 테스트 설정

- 테스트에서는 H2 인메모리 데이터베이스를 사용한다.
- 테스트 설정은 `src/test/resources/application.properties`에 작성한다.
- 별도의 MySQL 데이터베이스 없이 `./gradlew test`가 실행되어야 한다.

## 6. 회원가입

### 6.1 요청 URL

```text
GET  /members/new
POST /members
```

### 6.2 입력 항목

- 로그인 아이디
- 비밀번호
- 비밀번호 확인
- 이름
- 이메일

### 6.3 Validation

- 모든 항목은 필수이다.
- 로그인 아이디는 4자 이상 20자 이하이다.
- 비밀번호는 8자 이상이다.
- 비밀번호와 비밀번호 확인 값은 일치해야 한다.
- 이메일은 올바른 이메일 형식이어야 한다.
- 로그인 아이디는 중복될 수 없다.
- 이메일은 중복될 수 없다.

입력값에 오류가 있으면 회원가입 화면으로 돌아가고 오류 메시지를 표시한다.

회원가입이 완료되면 로그인 화면으로 이동한다.

```text
회원가입 성공 → /login
```

비밀번호는 데이터베이스에 평문으로 저장하지 않는다.

## 7. 로그인과 로그아웃

인증은 Spring Security Form Login과 HTTP Session을 사용한다.

### 7.1 로그인

```text
GET  /login
POST /login
```

로그인 화면에서 다음 값을 입력받는다.

- 로그인 아이디
- 비밀번호

로그인 아이디로 회원을 조회하는 `UserDetailsService`를 구현한다.

### 7.2 로그아웃

```text
POST /logout
```

로그아웃은 로그인한 사용자만 사용할 수 있다.

## 8. 게시글 목록 조회

### 8.1 요청 URL

```text
GET /articles
```

### 8.2 조회 조건

- 한 페이지에 게시글 10개를 표시한다.
- 작성일을 기준으로 최신 게시글부터 정렬한다.
- Controller는 `Pageable`을 Service에 전달한다.
- Service는 `Page<Article>`을 반환한다.

### 8.3 표시 항목

- 게시글 번호
- 제목
- 작성자
- 작성일

제목을 클릭하면 게시글 상세 화면으로 이동한다.

게시글이 없으면 다음 문구를 표시한다.

```text
등록된 게시글이 없습니다.
```

### 8.4 페이지 이동

목록 하단에 다음 기능을 제공한다.

- 이전 페이지
- 페이지 번호
- 다음 페이지

현재 페이지를 강조한다.

첫 페이지에서는 이전 버튼을 비활성화하고, 마지막 페이지에서는 다음 버튼을 비활성화한다.

## 9. 게시글 상세 조회

### 9.1 요청 URL

```text
GET /articles/{articleId}
```

### 9.2 표시 항목

- 제목
- 작성자
- 작성일
- 게시글 내용

게시글 내용의 줄바꿈이 유지되어야 한다.

화면 하단에는 목록으로 이동하는 버튼을 표시한다.

현재 로그인한 사용자가 게시글 작성자인 경우에만 수정과 삭제 버튼을 표시한다.

존재하지 않는 게시글을 요청하면 예외로 처리한다.

---

## 10. 게시글 등록

### 10.1 요청 URL

```text
GET  /articles/new
POST /articles
```

### 10.2 입력 항목

- 제목
- 내용

### 10.3 Validation

- 제목은 필수이다.
- 제목은 100자 이하이다.
- 내용은 필수이다.

입력값에 오류가 있으면 게시글 작성 화면으로 돌아간다.

게시글 작성자는 현재 로그인한 사용자의 로그인 아이디로 회원을 조회하여 설정한다.

등록이 완료되면 게시글 목록으로 이동한다.

---

## 11. 게시글 수정

### 11.1 요청 URL

```text
GET  /articles/{articleId}/edit
POST /articles/{articleId}/edit
```

수정 화면에는 기존 제목과 내용을 표시한다.

게시글 작성자만 수정할 수 있다.

권한 검사는 `ArticleService`에서 처리한다.

수정이 완료되면 게시글 상세 화면으로 이동한다.

---

## 12. 게시글 삭제

### 12.1 요청 URL

```text
POST /articles/{articleId}/delete
```

게시글 작성자만 삭제할 수 있다.

권한 검사는 `ArticleService`에서 처리한다.

삭제 버튼을 누르면 JavaScript의 `confirm()`을 사용하여 삭제 여부를 확인한다.

삭제가 완료되면 게시글 목록으로 이동한다.

## 14. 화면 구성

다음 템플릿을 작성한다.

```text
templates
├─ login.html
├─ logout.html
├─ members
│  └─ create.html
└─ articles
   ├─ list.html
   ├─ detail.html
   └─ form.html
```

`articles/form.html`은 게시글 등록과 수정 화면에서 공통으로 사용한다.

`/` 요청은 게시글 목록으로 리다이렉트한다.

### 14.1 공통 화면

- 화면 상단에 게시판 제목을 표시한다.
- 본문은 최대 너비를 지정하고 가운데에 배치한다.
- 로그인 상태에 따라 상단 메뉴를 다르게 표시한다.
- 모바일 화면에서도 자연스럽게 표시되도록 한다.

비로그인 상태에서는 다음 메뉴를 표시한다.

- 로그인
- 회원가입

로그인 상태에서는 다음 메뉴를 표시한다.

- 로그인 아이디
- 글쓰기
- 로그아웃

### 14.2 디자인 기준

- 페이지 배경은 연한 회색 계열로 설정한다.
- 주요 콘텐츠는 흰색 카드 형태로 표시한다.
- 카드에는 둥근 모서리와 약한 그림자를 적용한다.
- 입력 필드에는 테두리, 안쪽 여백과 포커스 효과를 적용한다.
- 주요 버튼은 파란색으로 표시한다.
- 삭제 버튼은 빨간색으로 표시한다.
- 오류 메시지는 입력 항목 아래에 빨간색으로 표시한다.
- 버튼과 링크에는 마우스 오버 효과를 적용한다.
- Tailwind CSS를 사용한다.

## 15. 예외 및 오류 처리

다음 상황은 오류로 처리한다.

- 존재하지 않는 회원 조회
- 존재하지 않는 게시글 조회
- 로그인 아이디 중복
- 이메일 중복
- 비밀번호 확인 불일치
- 다른 사용자의 게시글 수정 시도
- 다른 사용자의 게시글 삭제 시도

사용자 입력 오류는 해당 입력 화면에 메시지로 표시한다.

권한 오류나 존재하지 않는 데이터에 대한 처리 방식은 프로젝트 전체에서 일관되게 작성한다.

## 16. 단계별 구현 및 리뷰

다음 순서로 한 단계씩 구현한다.

1. Entity와 `schema.sql`
2. Repository
3. Service
4. Spring Security
5. Form과 Validation
6. Controller
7. Thymeleaf 화면
8. 권한 및 예외 처리

### 진행 규칙

- 한 번의 작업에서는 하나의 단계만 구현한다.
- 각 단계가 완료되면 구현을 중단하고 결과를 보고한다.
- 개발자가 변경된 코드를 리뷰한다.
- 리뷰 결과에 따라 수정하거나 현재 단계를 승인한다.
- 개발자가 승인한 후에만 다음 단계로 진행한다.
- 현재 단계가 승인되기 전에는 다음 단계의 코드를 미리 작성하지 않는다.
